The project in one minute

What exists

Detailed research and design: architecture, strategies, risk rules, exchange contracts, books, costs, security and implementation steps.

What comes next

The built local replay/PAPER app has an auditable ledger, realistic fees, restart recovery and a light dashboard. Core operation needs no AI key.

What remains unproven

Strategy profitability, account compatibility and extraordinary return claims remain unvalidated.

How it should work

Feed or replay → strategy → risk checks → durable order record → paper broker or separately armed exchange adapter

Python backend

uv, FastAPI, Uvicorn and SQLite. One execution owner; durable orders and recovery records.

Light React UI

Mode, freshness, cash, positions and costs. Pause, cancel and exit are distinct controls.

Optional AI

Research and explanations through LangChain Responses. No trading keys or risk overrides. Vector search is deferred.

Is it good enough right now?

For local replay/PAPER use: implemented. Offline verification is recorded; cleanup and remote CI verification continue. No complete CI pass is claimed.

For live trading: no. Actual fees, exchange behavior, order reconciliation, partial fills, outages and recovery still need verification. More documents cannot replace those tests.

The independent review found defects in illustrative trading-skill examples. Installed skills are research aids, not approved execution code.

Development rules

  • Small commits, each with one coherent purpose and a passing relevant check.
  • QA subagents test and review code before it is committed or pushed. Fix findings and rerun affected checks.
  • No Codex/AI attribution, generated-by labels or attribution trailers. Keep useful technical comments, type annotations and audit facts.
  • Paper mode first. No live orders in tests or CI. No credentials in Git.
